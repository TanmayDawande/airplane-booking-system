Front-End Design & Basic Database Connectivity

Length: ~3 Minutes
Teammate 1: Introduction & Interface Walkthrough
Face Visible on Camera

Assessment 9 Demonstration

Database Operations & Back-End Implementation

Length: ~4 Minutes
Teammate 1: Back-End Communication & Full CRUD Operations
  1. Back-End Architecture (0:00 - 0:45): Explain that Flask communicates with the database using parameterized queries to protect against SQL injection and manage transactions cleanly.
  2. INSERT Operation: On the Admin CRUD page ([/admin](http://127.0.0.1:5000/admin)), click "Schedule Flight (INSERT)". Enter flight `AI-999` from BOM to DEL with base fare ₹5,200. Execute query and point out the newly created flight in the table.
  3. UPDATE Operation: Click "Edit" on `AI-999`. Update the fare to ₹5,600 and change status to `DELAYED`. Show the updated values in the table. Verify in DB Studio with:
    SELECT flight_number, base_fare, status FROM flights WHERE flight_number = 'AI-999';
  4. DELETE Operation: Click "Delete" on flight `AI-999`. Confirm the dialog. Show the flight row disappear from the table and verify that `SELECT * FROM flights WHERE flight_number = 'AI-999'` returns 0 rows.
Teammate 2: Complex SQL Queries & Triggers
  1. Multi-Table INNER JOIN: Open Reports ([/reports](http://127.0.0.1:5000/reports)). Show the 5-table JOIN combining `bookings`, `passengers`, `flights`, `airlines`, and `airports`. Explain how foreign keys maintain relational links without data duplication.
  2. GROUP BY & Aggregations with HAVING: Show the Airline Revenue table. Explain how SQL aggregates total bookings (`COUNT`), gross revenue (`SUM`), and average ticket prices (`AVG`) with `HAVING gross_revenue > 5000`.
  3. Nested Subquery & Triggers: Show the High-Value Passengers report using a subquery `WHERE total_amount > (SELECT AVG(total_amount) FROM bookings)`. Conclude by viewing the Audit Logs tab on [/admin](http://127.0.0.1:5000/admin) to demonstrate database triggers capturing insert/update events.
Assessment 10 Demonstration

Complete Project Workflow and Functional Validation

Length: ~5 Minutes
Teammate 1: Search, Seat Map Selection & Passenger Entry
  1. Search Flights (0:00 - 0:45): Go to the home page ([/](http://127.0.0.1:5000/)), select Mumbai (BOM) to New Delhi (DEL), and click "Search Flights".
  2. Select Flight & Seat (0:45 - 2:00): Click "Select Seat" on flight `AI-101`. On the cabin map, point out occupied seats (red) and available seats. Click on seat `11C`. Show the price breakdown update dynamically for the selected seat.
  3. Input Validation & Error Handling (2:00 - 2:30): Attempt to submit with incomplete fields or invalid format to demonstrate client and server-side validation. Then enter valid passenger details.
  4. Submit Transaction: Click "Confirm & Pay". Highlight that this triggers an atomic ACID database transaction.
Teammate 2: Boarding Pass Generation, DB Verification & Cancellation
  1. E-Ticket / Boarding Pass Generation (2:30 - 3:15): Show the generated boarding pass with the generated PNR, passenger name, seat 11C, departure time, and barcode. Click "Print Boarding Pass".
  2. Database Transaction Verification (3:15 - 4:00): Note the generated PNR code. Switch to DB Studio ([/db-studio](http://127.0.0.1:5000/db-studio)) and run:
    SELECT b.pnr, b.seat_number, b.status, p.amount, p.payment_status FROM bookings b JOIN payments p ON b.booking_id = p.booking_id WHERE b.pnr = '<YOUR_PNR>';
    Verify that both the booking and payment records were inserted atomically.
  3. Booking Cancellation & Seat Release (4:00 - 4:45): Navigate to Manage PNR ([/my-bookings](http://127.0.0.1:5000/my-bookings)). Click "Cancel Booking". Show that status updates to `CANCELLED`, payment is refunded, and seat 11C is immediately released for re-booking.
  4. Conclusion (4:45 - 5:00): Conclude that all three assessments have distinct, verified demonstrations covering the complete DBMS curriculum.
